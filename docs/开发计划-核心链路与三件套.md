### 0.3 为什么不是「全量等价」

源项目生产代码 ≈23,600 行，但**默认关掉了近一半基础设施**（655 行上下文治理 `CONTEXT_STRATEGY=legacy`、混合检索 `HYBRID_RECALL_ENABLED=0`、精排未验证、漂移检测默认关、个人 Skill `SKILL_CATALOG_MODE=legacy`），且 `eval/verification/release-summary.json` 判词为 `"BLOCKED：三套正式release均未通过"`。

**这些能力在源项目里没有验收基线——没有基线就无法证明「等价」。** 这是范围收缩的实质理由，不是工期压力。

### P0 — 骨架与横切基座（18 人日）

4. `container.Build()`：唯一装配根，依赖注入

**交付物**：可编译可启动的空壳服务；`/health` 返回 `{"status":"ok","version":...,"commit":...}`。

**验收指标**

| # | 指标 | 目标 |
|---|---|---|
| A1 | `make run` 冷启动 | < 1s |
| A2 | `/health` 在 Postgres 断开时返回 **503** 且含 `db: down` | 必达 |
| A3 | `go-arch-lint` 检查 | 0 违规（domain 不 import infra/agent/presentation） |
| A4 | `golangci-lint` | 0 error |
| A5 | 构建产物 | 单一静态二进制 < 30 MB，`CGO_ENABLED=0` |

**测试要求**：L1 单元（domain 包已≥90%）；L3 集成脚手架（testcontainers 起 Postgres 的冒烟用例）。

**关键陷阱（必须在本阶段解决）**

- **`round()` 银行家舍入**：Python `round()` 是 round-half-to-even，Go `math.Round` 是 half-away-from-zero。`Money`、汇率、关税三处金额换算会分叉到「分」。**P0 就写 `RoundHalfEven` 并加差分测试**，不要等到 P2。
- **`OrderStatus` 线格式**：源项目是 `class OrderStatus(str, Enum)`，序列化为裸字符串 `"CONFIRMED"`。Go 必须实现 `MarshalJSON`/`UnmarshalJSON` 保持，否则前端契约破裂。
- **配置校验**：缺失必填项**直接报错启动失败**，不静默用默认值。

### P1 — 交易账本（24 人日）★ 最高风险

**开发内容**

1. **Postgres 事务模型重设计**（不是翻译——源项目靠 SQLite `BEGIN IMMEDIATE` 单写锁，Postgres 是 MVCC，该原语不存在）
2. 四个聚合表：`confirmation` / `inventory` / `order` / `operation_id`（幂等）
3. 两阶段提交：`PrepareConfirmation` → `ResolveConfirmation`
4. 库存**比较-更新**扣减（`WHERE stock >= qty AND unit_price_minor = ? AND currency = ?`，`rowcount != 1` 即失败）
5. `snapshot_hash`（确认单自 prepare 后未被篡改）+ `hmac.compare_digest` 恒时比较
6. `SessionClaim` CAS 写保护（`session_id + owner_id + revision + fence` 四元组）
7. 会话租约：30s 租期 + 5s 心跳续约；租约丢失 → 取消生产者并写 `SERVER_RESTART`

**交付物**：`infra/persistence/pg` 下的 `TradeStore` 与 `SessionStore`；迁移脚本。

**验收指标**

| # | 指标 | 目标 | 判定方式 |
|---|---|---|---|
| B1 | **并发幂等** | N=32 并发同一 `OperationID` → **恰好 1 笔交易** | 并发压力测试 |
| B2 | 库存不超卖 | 100 并发抢 10 件库存 → 恰好 10 单成功，库存 = 0 | 并发测试 |
| B3 | 事务原子性 | 注入 resolve 中途失败 → 订单、库存、幂等键**全部回滚** | 故障注入 |
| B4 | 幂等读取顺序 | 重试已提交的 `OperationID` → 返回原结果，**不新建第二笔** | 单元测试 |
| B5 | 价格漂移防护 | prepare 后改价 → resolve 失败并返回 `PRICE_CHANGED` | 单元测试 |
| B6 | 栅栏拒绝迟到写 | 租约过期后旧执行者写回 → `ErrStaleSessionWrite` | 单元+集成 |
| B7 | 冲突重试 | SERIALIZABLE 冲突自动重试 ≤3 次后放弃并告警 | 集成测试 |
| B8 | 账本写入 P95 | < 15ms（单实例，本地 Postgres） | benchmark |

**测试要求**：L1（≥90%）；**L4 并发与性质测试**（本阶段是重点）；L3 集成。

**必须保留的顺序语义（源码注释逐字）**

> 幂等读取已提交结果**先于**过期检查——「防止网络重试变成第二笔交易」。

```python
# 源项目原文，Go 侧语义必须一致
if row.status != "pending":
    if row.status != status:
        raise TradeStoreError("DECISION_CONFLICT", ...)
    return self._confirmation(row)   # 幂等读取先于过期检查
```

**哈希对齐**（若需与源项目数据互通）

```
sha256(json.dumps(v, ensure_ascii=False, sort_keys=True,
                  separators=(",", ":"), allow_nan=False))
```

### P4 — AG-UI 服务端（24 人日）

**开发内容**

1. AG-UI SSE 服务端（tRPC `server/agui`）
2. **运行 journal**：每事件 `event_id` + run 内单调 `Seq`，**先落库再推送**
3. **可恢复流**：`Last-Event-ID: {runId}:{seq}` 回放缺失事件
4. 运行租约监督 + 崩溃恢复（`SERVER_RESTART`）
5. A2UI v0.9 适配器（`createSurface` / `updateComponents` / `updateDataModel`）
6. 22 条 REST 路由（见附录 B）
7. 身份：demo / hmac 双模（严格 header 与键集校验）
8. 取消 / 屏蔽的运行控制

**交付物**：`presentation/**`。

**验收指标**

| # | 指标 | 目标 | 判定方式 |
|---|---|---|---|
| E1 | **断流续传** | 客户端在 seq=N 断开，重连后从 N+1 续，**无重复无缺口** | E2E |
| E2 | **游标连续性** | `seq != cursor+1` → 服务端明确报错「事件顺序有缺口」 | 单元测试 |
| E3 | 跨 run 游标拒绝 | 用 run A 的游标请求 run B → 拒绝 | 单元测试 |
| E4 | **重连不重复计费** | 重连只 GET journal，**绝不重新 POST 模型** | 集成测试（断言模型调用次数） |
| E5 | 崩溃恢复 | kill -9 服务 → 重建后 run 标记 `SERVER_RESTART`，事件可回放 | 故障注入 |
| E6 | A2UI v0.9 契约 | 三报文通过 schema 校验；`catalogId="globex.local/shopping-v2"` | 契约测试 |
| E7 | 非法 A2UI 拒渲染 | 版本号/组件树/`path` 任一不符 → 前端**拒渲染** | 前端单元测试 |
| E8 | 身份精确校验 | 键集多一个或少一个 → 401 | 安全测试 |
| E9 | 慢客户端不拖垮生产者 | 订阅者 channel 写满 → 丢弃并标 `lagged`，**生产者不阻塞** | 并发测试 |

**测试要求**：L1（≥85%，handler 用 `httptest`）；L2 契约；L3 集成；L4 并发；**L9 故障注入**。

**A2UI 兼容坑（必须在本阶段解决）**

tRPC 的 A2UI 翻译器硬编码 `a2ui/v0.8`（动作名 `beginRendering`/`surfaceUpdate`/`dataModelUpdate`），与源项目 **v0.9** 不兼容。缓解顺序：
1. planner 的 `WithInstruction` / `WithServerToClientSchema` 注入 v0.9 schema
2. 不行则 fork 翻译器的 source 标签
3. 最后手段：前端容错双版本（**不推荐**，削弱 E7 的严格校验闸门）

### P5 — 可观测三件套（40 人日）

**共享基座**

```
运行事件源 = eventbus(17 种事件) ⊕ OTel span ⊕ operational_metrics
                    ↓
            单一 RunEvent 流（ULID + Seq 单调）
        ┌──────────┼──────────┐
     逐条读      聚合读      切片读
   (回放/diff) (成本/延迟)   (A/B)
```

**开发内容**

1. **RunEvent 基座**：`RunEvent` / `Attrs` / `SchemaVer`；写事件走**异步有界队列**，队列满则**丢弃可观测事件并计数，绝不阻塞 Agent**
2. **内容寻址 blob**：`sha256(body)`，存 prompt 全文 / 模型响应全文 / 工具大结果
3. **脱敏在写路径上**（不是读路径）：手机号、邮箱、地址、支付信息、密钥形态
4. **保留策略**：原始 blob N 天后降级为仅存哈希
5. **功能一：轨迹回放与差分**——录制 / 回放 / 单步 / 两次运行 diff（按 `tool_call_id` 对齐）
6. **功能二：成本与延迟归因**——token 四维计量（`input`/`output`/`cached_input`/`reasoning`）、版本化价格表、延迟分层分解、rollup 物化
7. **功能三：Prompt·模型 A/B**——实验臂分组、统计显著性、LLM-judge 自动回归
8. 存储：Postgres `observability` schema（**独立连接池，不与交易账本共享事务**）

**交付物**：`application/observability`、`infra/observability`。

### 4.2 单元测试覆盖率要求（≥90%）

**总要求：加权行覆盖率 ≥ 90%。** 但**不搞全仓一刀切**——对需要外部服务的适配器强求 90% 只能靠写不assert的测试凑数。分档如下：

| 包 | 目标 | 理由 |
|---|---|---|
| `internal/domain/**` | **≥95%** | 纯逻辑，零 IO，无借口 |
| `internal/application/**` | **≥90%** | 用例编排，依赖全部用 fake |
| `internal/agent/**` | **≥90%** | 编排与中间件，模型用 fake model |
| `internal/presentation/**` | **≥85%** | handler 用 `httptest`；路由装配部分难以单测 |
| `internal/infra/**` | **不计入单元门禁** | 见下 |
| `internal/container/**`、`cmd/**` | **排除** | 装配代码，断言价值低 |

**`internal/infra/**` 的例外条款**

| 子包 | 处理 |
|---|---|
| 纯函数（`RoundHalfEven`、`transient.IsTransient`、脱敏器正则、哈希） | **纳入 L1，≥95%** |
| 需要外部服务的适配器（pg / qdrant / redis 客户端） | 由 **L3 集成测试**覆盖，不计入单元门禁 |
| 但**必须**满足：集成测试覆盖其全部公开方法 | 由 L3 的 `TestMain` 断言方法清单完整 |

> **这条不是放水**：infra 适配器的公开方法**全部**要有集成测试，只是它的失败模式（连接、超时、事务）用 testcontainers 验证才有意义，用 mock 验证等于自己骗自己。

**加权公式**

```
加权覆盖率 = Σ(包行数 × 包覆盖率) / Σ(包行数)   // 仅统计非排除包
门禁：加权 ≥ 90% 且 每个非排除包 ≥ 其分档阈值
```

**执行方式**

```makefile
cover:
	go test ./... -covermode=atomic -coverprofile=coverage.out -coverpkg=./internal/...
	go tool cover -func=coverage.out | tail -1
	go run ./scripts/coverage-gate -thresholds=coverage-thresholds.yaml -profile=coverage.out
```

`coverage-thresholds.yaml` 与代码同库存放、**走代码评审**——改阈值等同于改验收标准，不允许随手调低。

**覆盖率门禁规则**

1. 任一包低于阈值 → CI **失败**
2. 覆盖率**环比下降** → CI **失败**（不允许「这次先降一点，下次补」）
3. 新增文件覆盖率 < 90% → CI 失败

---

### 4.3 覆盖率不能替代断言（反自欺条款）

**90% 行覆盖率 + 没有断言的测试 = 0。** 防止这一点的唯一手段是变异测试：

| 手段 | 目标 | 说明 |
|---|---|---|
| **变异测试（gremlins）** | 全局杀死率 ≥70%，domain ≥80% | 若把 `>=` 改成 `>` 测试仍全绿，说明断言是假的 |
| 断言密度检查 | 每个测试函数 ≥1 个非 `NoError` 断言 | 拒绝「只调一次不出错就算过」 |
| 审查抽样 | 每阶段抽查 10% 测试文件 | 人工看断言是否真的在验行为 |

> **诚实声明**：覆盖率是**必要条件不是充分条件**。达到 90% 不代表正确，只代表没有大片未测代码。**正确性由 L4 并发测试、L5 变异测试、L8 评测共同背书。**

### F.3 `docker/backend.Dockerfile`

`frontend/nginx.conf` —— **SSE 三项必须齐**：

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    location /commerce/ {
        proxy_pass http://app:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        # SSE：三项缺一不可，否则流被缓冲、看板与对话都会「卡住不动」
        proxy_buffering off;
        proxy_cache off;
        add_header X-Accel-Buffering no;
        proxy_read_timeout 600s;
    }
    location = /health { proxy_pass http://app:8000; }
    location / { try_files $uri $uri/ /index.html; }
}
```

### F.5 镜像层的待核实项（P8 必须实测）

| # | 项 | 风险 | 处理 |
|---|---|---|---|
| 1 | **`node:20-alpine` 已 EOL** | 2026-04-30 起不收安全补丁；技术上 Vite 8 的 engines 是 `^20.19.0 \|\| >=22.12.0`，20.19+ **能构建**，但等于在无维护运行时上出货 | **改 `node:24-alpine`**（2026-09 的 Active LTS）。这是唯一需要下载的镜像 |
