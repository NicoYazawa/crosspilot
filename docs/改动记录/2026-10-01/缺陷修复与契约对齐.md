# 缺陷修复与契约对齐（全量审计后整改）

## 概述

对照 `docs/开发计划-核心链路与三件套.md` 对 P0–P8 做全量审计后，本轮只做**缺陷类整改**，
不含 D5–D10 的新功能开发（HITL 审批、四级 token 预算、限流、Skill 注册表、dislike 全量注入、
偏好版本冲突）。

整改分两条线：

1. **契约对齐**：路由前缀回到附录 B 的 `/commerce/*`，鉴权从 HMAC 换成附录 C#5 的 JWT 严格键集校验。
2. **缺陷修复**：安全、死代码、假测试、门禁失效四类。

改动范围涉及 Go 后端、前端、nginx、E2E 与 CI 门禁配置。

## 一、修复的缺陷

### 1.1 安全：身份可被请求体覆盖（真实越权）

`internal/presentation/agui/handler.go` 的 `SubmitRequest` 原先直接从 JSON 请求体读
`buyer_id` / `session_id`。中间件按 JWT 算出的身份，会被请求体里的一个字段直接推翻——
任何持有效令牌的调用方都能以他人身份下单。

修法：两个字段标 `json:"-"`，身份只从中间件取；取不到买家身份直接 401，不放行到业务层。

```go
req.BuyerID = presauth.BuyerFrom(r.Context())
req.SessionID = presauth.SessionFrom(r.Context())
if req.BuyerID == "" {
    writeError(w, deps.Logger, http.StatusUnauthorized, "missing_buyer",
        errors.New("请求未携带买家身份"))
    return
}
```

**验证**：`TestSubmitEndpoint_CallsSubmitter` 断言请求体里塞 `buyer_id:"b1"` 会被忽略；
`TestSubmitHandler_RejectsWithoutIdentity` 断言无身份时 401 且 submitter 未被调用。
线上实测：带合法令牌 200，无令牌 401，错误密钥 401。

### 1.2 安全：孤儿鉴权代码与「供养它的测试」

`internal/presentation/agui/auth.go`（HMAC 中间件）在路由切到 `presauth.Middleware` 后已无任何
调用方，仅剩它自己的 13 个测试引用它——测试在，代码看起来就还活着。整文件连同测试一并删除。

### 1.3 进程级 panic：`Build` 只能构造一次

`internal/agent/observability/metrics.go` 用 `expvar.NewInt` 注册计数器，而 `expvar` 是**进程级**
扁平命名空间，重复注册会 **panic**。后果是同一进程内第二次 `Build` 直接崩，测试
`TestBuildSucceedsWithoutDependencies` 因此失败。

修法：先 `expvar.Get` 查再注册，加互斥锁。

```go
func newExpvarInt(name string) *expvar.Int {
    if v := expvar.Get(name); v != nil {
        if i, ok := v.(*expvar.Int); ok { return i }
    }
    return expvar.NewInt(name)
}
```

同 `name` 复用同一组计数器（expvar 本身如此），文档注释已改，不再声称「按 Emitter 分桶」。

**验证**：`/observability/metrics` 在部署中返回真实计数 `{"queue_depth":0,...}`，且同进程可重复构造。

### 1.4 死代码

删除整包与约 38 个符号（含 `agui/auth.go`、`internal/agent/shopping/context.go` 等）。删除后
`go build`/`go vet`/lint 均干净，无残留引用。

### 1.5 假测试

修掉 10 处「接口层绿、实现层一行没跑」的用例。其中最具代表性的一处：

`Bridge.Cancel` 是 `POST /commerce/ag-ui/runs/{id}/cancel` 背后**真正的实现**，但此前只有
`agui` 包用假 `RunCanceller` 在 HTTP 层断言了 200/404/503——「取消是否真的能打断推理」
从未被验证，`Cancel` 覆盖率 0%。

补测后断言可观测后果而非返回值为真：阻塞在 `<-ctx.Done()` 的假 Orchestrator 驱动 `Run`，
断言 Cancel 后 Run 确实返回、`ctx.Err()==context.Canceled`、journal 落下 `run_error` 而非挂死。
自证：把 `v.(context.CancelFunc)()` 注释掉后该用例精确失败（
`Cancel 未真正中断 Run：Run 一直挂着未返回`），随后还原。

### 1.6 覆盖率缺口补测（三处，均为真实测试）

门禁修好后暴露出三处真实的覆盖缺口：

| 包 | 改前 | 改后 | 说明 |
|---|---|---|---|
| `internal/presentation/auth` | **无任何测试** | 97.5% | JWT 严格键集校验器，安全关键，此前一行测试都没有 |
| `internal/presentation/commerce` | 53.9% | 88.3% | 六个 handler 完全没测：getOrder / cancelOrder / listConfirmations / placeOrder / getConfirmation / toDomain |
| `internal/application/orderflow` | 86.0% | 94.2% | `Bridge.Cancel` 0% → 100% |

`auth` 的用例覆盖 alg 混淆（`none` / `RS256`）、header 与 claims 的**键集严格性**（多一个 `kid`、
把 `iss` 换成 `issuer`）、`strict_aud` 数组形式、时钟偏移窗口的**两侧边界**、以及全部畸形
Authorization 头形态。时间维度用可注入 Clock，测试里没有任何 `time.Sleep`。

**反「假测试」自证**（不是只看用例存在与否）：

- 独立复核：把 `buyerOf` 改成返回常量 `"someone-else"` 后，commerce 的 7 条用例立刻变红（身份透传断言真的在起作用）。
- `DemoIdentity` 去掉「已有身份不覆盖」守卫 → `TestDemoIdentity_不覆盖已有身份` 红。
- `checkSignature` 把常量时间比较改成恒不成立 → 签名篡改与错误密钥两条红。
- `writeServiceError` 把 `OWNER_MISMATCH` 由 403 改成 404 → 映射表用例红。

### 1.7 契约对齐（附录 B / C#5）

| 项 | 改前 | 改后 |
|---|---|---|
| 交易链路前缀 | `/orders`、`/confirmations` | `/commerce/orders`、`/commerce/confirmations` |
| AG-UI 前缀 | `/agui/*` | `/commerce/ag-ui/*` |
| 鉴权 | 前端 HMAC 签名 | JWT HS256 严格键集校验 |
| nginx | `location /agui/` | `location /commerce/ag-ui/` + `location /commerce/` |
| vite 代理 | `/agui` | `/commerce` |
| E2E fixtures | `/agui/*` | `/commerce/ag-ui/*` |

JWT 校验要点：header 键集精确 `{alg,typ}` 且 `alg=="HS256"`；claims 键集精确 `{sub,iat,exp,iss,aud}`；
`strict_aud`（aud 必须是字符串）；常量时间比较；±1 分钟时钟偏移。会话**不进** claim，只走
`X-Session-ID` 头。

前端的 HMAC 方案必须废弃：它要求把共享密钥打进浏览器包，任何人打开 devtools 就能伪造任意买家身份。
JWT 由签发方持钥，前端只负责携带。

### 1.8 前端

- 新增 `src/lib/auth.ts`（`buildAuthHeaders`），替换被删的 HMAC 签名器。
- `A2UI_CATALOG_ID` 曾被 base64 混淆以绕开 lint 禁词——协议常量变得不可搜索，方向是反的。
  改为收窄规则，只放行 `globex.local/shopping-v2` 这一个字面量：

  ```js
  selector: "Literal[value=/globex/i]:not([value='globex.local/shopping-v2'])"
  ```

### 1.9 门禁失效

**lint**：`.golangci.yml` 之前会扫 `frontend/node_modules`（其中 `flatted` 包自带 Go 源码），
污染门禁读的「新增问题数」；另有一处重复的 `unconvert` 条目。修复后全仓 **115 → 0**。

**覆盖率**：`scripts/coverage-gate` 的两个问题一并修掉。

- **pg 门槛被架空**：`internal/infra/persistence/pg` 单设 min 70，但它整体落在更宽的
  `internal/infra/persistence/` 豁免之下（豁免优先于规则），该规则永远不生效。门禁新增
  「死规则」检测——整体落在豁免之下的规则、或被更宽规则覆盖的规则，直接报错。
- **加权覆盖率从未计算**：计划 §4.2 要求 Σ(包语句数 × 包覆盖率)/Σ(语句数) ≥ 90%，实现里没有。
  现已计算：**92.0%（3401 条语句）**。
- `scripts/` 由「`min: 0` 的规则」改为**豁免**：规则计入加权分母，工具包 0% 会把加权拉到 90 以下，
  让整条加权门禁永远无法通过。

四次单跑（隔离环境，不叠加其他测试）：

| 运行 | P50 | P95 | 结论 |
|---|---|---|---|
| 1 | 15.29ms | 17.61ms | 通过 |

而 P95 量的正是尾部。

**没有下调阈值，没有删除或 skip 该用例。** 阈值等同验收标准，且 CI 还在这条用例之上叠加了
`-race`（Taskfile `test:race`）与全包并行，只会更差。

建议（需决策，故未擅自实施）：把 B8 的延迟测量从共享的 `go test ./...` 中移出，改为
独立的串行性能 job（`-p 1`、不加 `-race`），阈值与断言原样保留。测 SLO 时旁边有 20 个包在抢 CPU，
测的是机器不是代码。

**缺失（10）**，全部落在本轮明确排除的 D5–D10 范围内，或属路径命名差异：

| 附录 B 路由 | 状态 |

| `/internal/metrics`、`/internal/metrics/summary` | 实现在 `/observability/metrics`（P5 交付，前端与 E2E 已在用） |

未添加桩实现：桩会让「这条路由存在」变成假信号，不如让缺口可见。

**额外多出（不在附录 B）**：`/health/live` 与 `/observability/*` 五条（P5 交付）。

**处置**：代码不动，把交付状态标注到计划文档本身（附录 B 表下新增「交付状态（2026-10-01 实测）」
小节），逐条写明 10 条缺失路由的归属。不改代码是因为缺的全在已排除范围内，
加桩会让「路由存在」变成假信号。标注在计划里而不是只写在改动记录里，
是为了让「22 条 REST 路由」这个验收指标不再被读成「已交付 22 条」。

### 3.2 `/observability/*` 无鉴权 —— **已处置（收口暴露面）**

补充定性：这一组不只是「指标没保护」。`replay` / `cost` / `diff` 返回的是 journal 原始事件与
运行数据，而 `run_start` 载荷含 `buyer_id` / `session_id` / `query`（见
`internal/application/orderflow/ports.go`）；run_id 又是 `run_<unixNanos>`，**可按时间戳穷举**。
即：无需任何凭据即可读回他人的下单原话与会话标识。

（如实说明：本地没有真实 LLM key，`POST /commerce/ag-ui/run` 返回 `submit_failed`、journal 中
未留下 run，因此**未能端到端实测**「读回他人 query」；上述结论基于代码路径。已实测的是
`/observability/metrics` 无凭据返回 200。）

处置（不动 JWT 契约）：

- `frontend/nginx.conf` 不再代理 `/observability/`；
- `docker-compose.yml` 的 app 端口改为只绑 `127.0.0.1`（运维本机仍可 curl 排障，同网段不可达）。

**代价（已知并接受）**：容器部署下交付界面的 Replay / Cost / Diff 面板拿不到数据。
E2E 抓不到这个回归，因为它 mock 后端。要让面板恢复，得先给这组接口真正的鉴权
（静态 token 或前端携带令牌），而不是靠「不代理」兜底。

### 3.3 交付的 compose 部署里前端无法鉴权 —— **已处置（本地走 demo 身份）**

问题：`docker-compose.yml` 给 app 设了 `AUTH_JWT_SECRET`（设了就关闭 demo 身份兜底），
但 `frontend/Dockerfile` 没有 `ARG VITE_AUTH_TOKEN`、compose 也没传 build arg，
而 `ShopView.tsx` 的令牌来源恰恰是 `import.meta.env.VITE_AUTH_TOKEN ?? ''`。
即 **`docker compose up` 出来的界面，调自己的后端会全线 401**（实测：无令牌
`/commerce/orders` → 401，前端侧不可能带上令牌）。

处置：本地栈默认走 demo 身份兜底，开箱可用且**零凭据进前端包**。

- `.env` 里 `AUTH_JWT_SECRET` 默认注释掉（该变量在 `config.go` 中并非必填，
  设了才启用鉴权；原 compose 注释「空字符串会触发 server 报错」是错的，已改正）；
- `docker-compose.yml` 注明生产必须设，并写明设了之后前端需要一个运行时换令牌的身份服务。

**刻意没做**：给 Dockerfile 加 `VITE_AUTH_TOKEN` build arg。它改动最小，但把长期凭据打进
JS bundle——正是从 HMAC 换到 JWT 时否掉的那个模式。生产正解是运行时向身份服务换令牌，
那属新功能，不在本轮范围。

附带产出 `scripts/dev-token.sh`：按附录 C#5 契约签发本地令牌，用于在「已开启鉴权」的部署上
手工验证后端链路（前端拿不到令牌时，后端链路仍需可验证）。已实测：有效令牌 200、无令牌 401。

### 3.4 `frontend/node_modules` 里的 Go 包属于本模块 —— **未处置，仅记录**

`go list ./...` 会列出 `github.com/NicoYazawa/crosspilot/frontend/node_modules/flatted/golang/pkg/flatted`
——`flatted` 这个 npm 包自带 Go 源码，且其目录下没有嵌套 `go.mod`，于是它是**本模块的一部分**：
会被编译、被 `go test` 跑到。（目录名不是 `testdata`，也不以 `_` 或 `.` 开头，go 工具链不忽略它。）

已在 lint 与覆盖率两处豁免它，门禁结论不受影响。若要彻底移出，需在 CI 各 target 用
`go list ./... | grep -v node_modules` 过滤。
