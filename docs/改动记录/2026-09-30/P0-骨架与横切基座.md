# P0：骨架与横切基座

日期：2026-09-30
范围：整个仓库的第一次落地（构建入口、依赖方向、配置、基础设施、可观测、接口层、装配、进程入口）

---

## 计划

目标不是「能跑业务」——业务在 P1–P5——而是让下面四条在 CI 上可以被强制：

1. 依赖方向只能由外向内，领域层不认识数据库与 HTTP；
2. 配置在启动期一次性校验完，缺必填项就直接启动失败；
3. 依赖不可用时进程照样启动，由 `/health` 如实报告，而不是崩溃重启；
4. 质量门禁（格式、lint、架构、测试、覆盖率）一条命令跑完。

对应 `docs/开发计划-核心链路与三件套.md` 中 P0 的验收项 A1–A5。

计划阶段确定的几项取舍：

| 取舍 | 选择 | 理由 |
|---|---|---|
| 金额表示 | `github.com/govalues/decimal` | 浮点不能用于钱；定点库能承载币种小数位与舍入策略 |
| 构建入口 | Taskfile | 本机无 `make`；Task 一份配置跨 Windows/macOS/Linux |
| 工具链 | `go run <module>@<版本>` | 版本钉在 Taskfile，本地与 CI 行为一致，开发机无需预装二进制 |
| 架构检查 | **仓库自带的 Go 测试** | 见下方「回归」第 3 条 |
| 前端 | 仅 `frontend/.gitkeep` 占位 | P6 才动，P0 只为 CI 预留路径 |

实现风格上的一条硬要求：**不逐行对应另一套实现的写法**，借思路、用 Go 惯用法重写。
因此代码注释只说明函数做什么，不出现任何语言或来源项目的字样。

## 实现

### 构建与质量门禁

- `Taskfile.yml` — 任务：`fmt` `fmt:check` `lint` `arch` `vuln` `test` `test:race`
  `cover` `cover:gate` `check` `build` `run` `clean` `migrate:up/down`
  `docker:up/down/reset/logs`。
- `.golangci.yml` — golangci-lint v2 配置。仅两处刻意的豁免，均写明理由：
  领域值对象按值传递（`hugeParam`）、测试文件不强制 `noctx`。
- `coverage-thresholds.yaml` + `scripts/coverage-gate/` — 按包设定覆盖率阈值。
  规则是**豁免优先于阈值**，且未纳入管理的包会报错（宁可吵，不可静默放行）。
- `.github/workflows/ci.yml` — Linux job 跑完整门禁（含竞态检测），
  Windows job 跑依赖方向与构建。
- `eval/verification/2026-09-30-P0-验收记录.md` — 本轮的原始验收证据。

### 领域层 `internal/domain/`（零外部依赖）

- `catalog/` — `Money`（`decimal` 支撑，含币种小数位归一与舍入）、`Currency`、
  `ExchangeRate`、`Product`、`ProductSearchSpec`、`ports.go`。
- `order/` — `Order`（状态机 + JSON 编解码）、`Line`（小计现算，不存字段，
  避免单价/数量/小计三者互相矛盾）、`Address`、`Status`、`ports.go`。
- 每个上下文一个 `errors.go`，错误一律返回不 panic。

覆盖率：`catalog` 100%、`order` 100%。

### 配置 `internal/config/`

- 显式 `Load()` / `LoadFrom(Lookup)`，**import 期无副作用**，测试可注入环境表。
- 错误一次性汇总返回，不遇到第一个就中断——一次启动看到全部问题。
- `Secret` 类型：`String`/`GoString`/`MarshalJSON`/`LogValue` 全部打码，
  只有 `Reveal()` 能取明文。整份配置丢进结构化日志也不会泄漏。
- 范围校验前置到读取时（`boundedInt32`），避免超界配置被静默截断成另一个数。

### 基础设施 `internal/infra/`

- `postgres/` — `pgxpool` 惰性构造（`MinConns: 0`），迁移执行器按 schema 版本表跳过已应用项。
- `redis/` — 惰性客户端。
- `logging/` — `log/slog` 自定义 Handler，自动带上 `request_id`/`session_id`/`trace_id`/`run_id`。

### 可观测 `internal/observability/`

- `otel.go` — OTLP/HTTP 直连导出（trace + metric），Endpoint 为空即关闭导出；
  `parseEndpoint` 显式区分明文与 TLS，协议非 http/https 直接报错。
- `redact.go` — 白名单脱敏骨架。

### 接口层与装配

- `presentation/http/` — chi 路由、请求 ID、panic 恢复、CORS 精确来源白名单
  （不支持通配符）、`/health` 与 `/health/live` 分离。
- `container/` — 唯一装配根，依赖只在这里创建并向下注入。
- `cmd/server` — 信号驱动的优雅关闭（关闭用新 context，信号 context 此时已结束）。
- `cmd/migrate` — 先探测连通性再执行迁移，把「连不上」和「脚本有问题」区分开。

## 回归

本轮修掉了四个「绿着但没用」的问题。它们都不是编译错误，而是门禁/指标本身失真。

### 1. 架构检查工具在 Windows 上全量误报

外部的架构检查工具在本机把**每一条项目内导入**都判为违规，包括同组件内部的导入。
读该工具的解析代码后定位到：它用 `/` 去裁剪 `filepath.Glob` 在 Windows 上返回的
反斜杠路径，裁剪不生效，导入路径变成绝对路径残片，精确匹配随即全部失败。

处理：删除该工具的配置，改为 `tools/arch/arch_test.go`——用标准库 `go/parser`
直接读导入声明。任何平台结论一致，随 `go test ./...` 一起跑，也不引入额外供应链。

配套加了四条自测（`TestUnder`/`TestIsStdlib`/`TestAllowedRejectsCrossLayerImports`/
`TestComponentOf`）：一个「永远返回 true」的检查器和没有检查器是一样的，
必须证明规则本身能拦住东西。

### 2. 覆盖率前缀写法导致规则静默失效

带尾斜杠的前缀（`.../internal/config/`）匹配不上包本身（`.../internal/config`），
于是阈值与豁免**双双不生效**，而输出看上去一切正常。改为同时锚定包本身与其子树，
并让豁免优先于阈值。

### 3. `-race` 在本机根本跑不起来

本机没有 C 编译器，`CGO_ENABLED=0` 是这台机器的 Go 默认值，`-race` 直接报错退出。
原先 `task test` 写死 `-race`，意味着这条门禁**在开发机上必然失败**——没人会跑的
门禁等于没有门禁。处理：`task test` 不带竞态检测，新增 `task test:race`，
竞态检测交给 CI 的 Linux job（Ubuntu 自带 gcc）。

### 4. `/health` 在依赖失联时反而变慢（2160 ms → 376 ms）

「依赖挂了」正是健康检查最该快速回话的时刻，实测却是最慢的时刻。两个原因：

- 各项探测串行执行，耗时是各项之和；
- Redis 客户端默认在拨号失败时重试 5 次，每次都要等一个拨号超时，并退避。

处理：探测并发执行并叠加整轮 1 秒预算（探针即便自己不遵守超时约定也不能拖住响应）；
Redis 客户端关闭内部重试与拨号重试。另外把 Redis 客户端自身的日志转接进 `log/slog`
——它原先直写 stderr，绕过日志配置也带不上关联字段。

### 5. lint 清零

首轮 38 个问题（errcheck / errorlint / gocritic / gosec / noctx / revive）全部处理，
其中 `errorlint` 与 `gosec` 的修复是实质性的：错误包装改用 `%w` 保留链条，
窄化转换补上范围检查而不是加豁免。

## 真实外部链路

- 拉起 postgres:18-alpine / redis:8.8.2-alpine / qdrant/qdrant:v1.19.0 三个容器。
- 对真实 Postgres 执行迁移：首次应用 1 步 → 再执行 0 步（幂等）→ 回滚 1 步 → 再升 1 步。
- 依赖齐备：`/health` 200 `{"db":"up","redis":"up"}`。
- 仅停 Postgres：`/health` 503 `{"db":"down","redis":"up"}`，进程不退出。
- 恢复 Postgres：**不重启进程**即回到 200。
- 依赖全停：`/health` 503 `{"db":"down","redis":"down"}`。
- `docker compose` 在未设置 `POSTGRES_PASSWORD` 时直接报错，不以明文默认值启动。

## CI

推送 `main` 后首次运行即全绿：<https://github.com/NicoYazawa/crosspilot/actions/runs/36605334327>。
Linux job 跑通格式 / 静态检查 / 依赖方向 / 单元测试（含竞态检测）/ 覆盖率阈值 / 构建 / 体积上限；

## 已知缺口（不得以「测试通过」掩盖）

1. **`internal/infra/postgres` 覆盖率 42.5%，已豁免。** 未覆盖的是迁移执行器内部
   路径，它需要真实 Postgres。目前只有人工端到端执行覆盖它，**没有自动化测试**。
2. **竞态检测在本地跑不了**（本机无 C 编译器）。CI 上已验证有效，本机不执行。
3. **Qdrant 只有配置、没有代码路径**，健康检查也不探测它。
4. 性能数字来自本机单次测量，未重复采样，**不代表生产表现**。
5. CI 只跑过一次、只覆盖首次提交这一个版本；它作为门禁的可靠性需在后续提交中观察。
